《智惠本草》后端设计需求文档 (Technical Design Doc)
一、 系统架构要求通信协议：除了标准的 HTTPS 接口，必须支持 MQTT 或 WebSocket 协议，用于实时驱动线下出纸机硬件 。核心逻辑：采用轻量化微服务架构，确保在校园、医院等高峰期（如课间、诊间）的高并发取纸请求下系统稳定 。
二、 核心功能逻辑与接口设计
1. 设备与物理网管理 (IoT Hub)心跳检测：后端需每隔固定时间（如30s）接收硬件发送的心跳包，实时更新数据库中设备的“在线/离线”状态 。库存预警：当出纸次数接近单台设备最大容量时，触发预警逻辑，向运营管理部推送补货通知 。指令下发：接收前端支付成功回调后，后端需通过 MQTT 向指定 device_id 发送“出纸”十六进制指令。
2. 交易与激励逻辑 (Transaction & Reward)支付回调处理：对接微信支付 API，确保支付状态异步确认的安全性。答题激励算法：验证逻辑：接收前端提交的选项 ID，比对数据库答案 。券包发放：若答对，后端需在 user_coupons 表中生成一条关联特定用户 ID 的“免费取纸券”记录 。防刷机制：限制单个用户每天通过答题获得免费券的上限次数。
3. 中医药知识图谱管理 (CMS & AI)随机题库引擎：根据用户画像或当前节气，从 quiz_pool 中随机抽取 3-5 道中医药常识题 。AR 资源下发：后端存储 3D 模型文件（.glb 或 .usdz 格式）的 URL 地址，并在前端触发识别时下发对应的模型元数据 。三、 数据库核心表结构设计（草案）表名关键字段 (Fields)说明Usersopenid, points, role_type用户基本信息及积分 Devicesdevice_id, location_gps, paper_stock, status设备物理位置、余纸量及在线状态 Quiz_Bankid, question, options, answer, category中医药题库，包含题目类别（如：本草、经络） Ordersorder_sn, user_id, device_id, pay_status, is_free取纸记录，区分付费取纸和答题兑换取纸 Couponscoupon_id, user_id, status (unused/used/expired)答题获得的免费兑换券管理 
四、 安全与性能需求
高并发预留：针对校内食堂等高频场景，后端接口需支持分布式缓存（如 Redis），缓存设备状态和题库，减少数据库直接 IO。
数据安全：所有涉及支付、用户信息、管理权限的 API 必须经过 JWT (JSON Web Token) 校验。审计日志：记录每一台设备的每一次出纸动作、故障上报日志，以便财务管理部进行精准核算和审计 。
五、 后端运维与治理支持热力图统计接口：聚合 Orders 表中的地理位置数据，输出各时段用纸密度，供管理方决策 。网格化监控：提供 API 接口支持“云运维中心”，实现故障自动派单流程 。
